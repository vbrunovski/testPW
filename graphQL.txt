query GetCharactersList {
  characters {
    # Объект info содержит метаданные о списке
    info {
      count
      pages
      next
    }
    # В results лежат сами объекты персонажей
    results {
      name
      status
    }
  }
}

Разбор
Когда ты работаешь с REST, сервер часто присылает данные в 
духе results: [...] и где-то в хедерах или корне прячет общее 
количество страниц. В GraphQL всё должно быть в схеме.

Зачем нужен info?
count: Общее количество персонажей в базе (сейчас их больше 800).

pages: Сколько всего страниц по 20 персонажей (стандартный размер пачки).

next: Номер следующей страницы. Если там null — ты дошел до конца.

Без этого объекта фронтенд не поймет, рисовать ли кнопку "Загрузить еще" или сколько цифр вставить в пагинатор.

Твое микро-задание прямо сейчас:

Посмотри в правую вкладку "Docs" в Playground.

Нажми на Query.

Найди там characters.

Посмотри, какие еще поля, кроме name и status, ты можешь вытащить из results.
