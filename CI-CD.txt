1. CI (Continuous Integration) — Непрерывная интеграция
Это практика, при которой разработчики часто (несколько раз в день) сливают свой код в общую ветку.

Для SDET: Как только код слит, автоматически запускаются твои тесты. Если они 
упали — интеграция не прошла. Цель — найти баги как можно раньше.

2. CD (Continuous Delivery / Deployment) — Непрерывная доставка/развертывание
Delivery: Код готов к выпуску, но кнопку «Задеплоить» нажимает человек.

Deployment: Всё происходит полностью автоматически. Если тесты прошли — 
новый код сам летит на сервер к пользователям.

3. Jenkins / Github Actions / Gitlab
Это инструмент CI/CD. Он сам ничего не программирует, он управляет.

Он умеет просыпаться по расписанию или событию.

Он знает, когда вызвать Git, когда запустить тесты, а когда отправить отчет.

Это мозг автоматизации.

4. Job (Джоба / Задача)
Это конкретная единица работы в Jenkins.

Представь, что Jenkins — это операционная система, а Job — это установленная программа.

В джобе прописано: что качать, какие команды запускать и куда слать отчет.

5. Pipeline (Пайплайн / Конвейер)
Это современный способ описания Job с помощью кода (Pipeline as Code).

Если обычная джоба — это набор галочек в интерфейсе, то Pipeline — это скрипт (обычно на языке Groovy), 
который описывает весь путь продукта от «взяли код» до «выкатили отчет».

Пайплайн делится на этапы (Stages): Build, Test, Deploy.

Что еще НУЖНО знать SDET:
Artifacts (Артефакты)

Это результат жизнедеятельности джобы. Для тестировщика это чаще всего отчеты 
(HTML, XML) или логи. Это файлы, которые Jenkins сохраняет после сборки, 
чтобы их можно было скачать и посмотреть.

Agent / Node (Агент или Нода)

Agent — это компьютер или Docker-контейнер, на котором физически запускаются твои тесты.

Зачем это SDET? Тесты могут требовать много памяти, и их часто запускают на отдельных мощных агентах.

Trigger (Триггер)

Условие, при котором запускается джоба.

Webhook: Пришел сигнал из GitHub (кто-то запушил код).

Cron: Пришло время (например, полночь) - запускается код.


Шпаргалка для студента на примере библиотеки(По версии GEMINI :D ):

GitHub — это библиотека (храним код). SCM - Source Code Management 
Jenkins — это библиотекарь (следит за порядком).
Pipeline — это инструкция (что делать, если принесли новую книгу).
Автотесты — это проверка на наличие опечаток в этой книге.
CI/CD — это весь процесс от написания страницы до появления книги на полке.
